# Code Review: Phase 1.5 Agent Completion Plan

**Status:** ⚠️ Needs Revisions (Critical Issues Found)

## 🚨 Critical Issues

### 1. Missing `error` Event on Decision Failure (Task 2 & 4)
**Issue:** Task 2's goal explicitly states: "runner 不发 decision_artifact，改发一条 error 事件提示用户" when `current_price=0`. However, in the Task 4 rewrite of `run_agent`, if `decision_card` is `None` (which it will be when the guard triggers), the code simply skips yielding the `decision_artifact` and yields `{"type": "done"}`. It never yields the required `error` event.
**Impact:** The frontend will silently finish without showing the user why the decision card wasn't generated.
**Recommendation:** In `run_agent` (Task 4), after awaiting the graph, add a check:
```python
if graph_result.get("intent") == "decision_failed":
    yield {"type": "error", "message": "获取股票数据失败，无法生成决策卡。"}
```

### 2. Foreign Key Constraint Violation in Task 7
**Issue:** In Task 7, `decisions.create_decision` uses `thread_id=req.thread_id or decision_id`. If the API is called without a `thread_id`, it uses the newly generated `decision_id`. However, it never creates a corresponding thread in the `threads` table for this `decision_id`.
**Impact:** SQLite will throw an `IntegrityError` (FOREIGN KEY constraint failed) when inserting into `decisions`, causing persistence to fail.
**Recommendation:** If `req.thread_id` is not provided, the backend must create a new thread in the `threads` table before creating the decision, OR the frontend must guarantee it always passes a valid `thread_id`. If relying on the frontend, change `thread_id=req.thread_id or decision_id` to just `req.thread_id` and handle the `None` case properly (e.g., skip persistence or throw an error early).

## 🟡 Important Issues

### 3. Flawed Concurrency UX (Task 4)
**Issue:** Task 4 aims to run the graph and LLM concurrently. However, it streams the LLM *first* (`async for text in _stream_llm_text(...)`) and only *then* awaits the graph (`await graph_task`) to yield `tool_trace` events.
**Impact:** `tool_trace` events are not streamed in real-time as the tools execute. Instead, they are buffered and dumped all at once at the end of the LLM response. If the LLM response finishes before the graph, the user sits in silence waiting for the graph, then everything pops out at once.
**Recommendation:** To truly interleave tool traces and LLM text, you need to read from both the `graph_task` (if it supports streaming events) and the `_stream_llm_text` generator concurrently using `asyncio.as_completed` or an `asyncio.Queue`. Alternatively, have the graph yield events into an async queue that the runner yields to the client alongside text deltas. If you just want a simple fix, at least accept that traces won't be real-time in this plan, but update the documentation to reflect this UX compromise.

### 4. Message Archival Data Loss (Task 6)
**Issue:** In `useAgentStream.ts`, the `user` message is POSTed to the backend in the `finally` block *after* the LLM stream finishes.
**Impact:** If the user closes the browser tab, refreshes, or if the network disconnects during the stream, the user's message is never saved to the backend.
**Recommendation:** Move the archiving of the `user` message to *before* the SSE fetch call begins, immediately after the thread is created. Only the `assistant` message should be archived in the `finally` block.

## 🔵 Minor Issues

### 5. Deprecated `tempfile.mktemp()` in Tests (Task 5 & 7)
**Issue:** `tempfile.mktemp()` is explicitly deprecated in Python due to security and race condition issues.
**Recommendation:** Use Pytest's built-in `tmp_path` fixture or `tempfile.NamedTemporaryFile(delete=False).name` instead to generate temporary SQLite database paths safely.

### 6. Client-Generated Thread IDs (Task 5/6)
**Issue:** The frontend creates a `local-xxx` thread ID, POSTs to create a thread, gets a server-generated ID, and has to do complex state mapping to replace the local ID with the real ID.
**Recommendation:** It's often simpler to allow the frontend to optionally provide an ID (like a UUID) in `ThreadCreateReq`. This eliminates the need to map IDs and simplifies `useAgentStream.ts` significantly.
